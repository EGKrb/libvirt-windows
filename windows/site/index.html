libvirt, native on Windows.

An unofficial port of libvirt 12.9.0 to Windows x64: virsh, the daemons and QEMU guests accelerated by the Windows Hypervisor Platform. libvirt's own code with its platform layers ported, so the same API, XML and commands.

What it does

Tested on Windows 11 with Ubuntu 24.04 guests.

The libvirt daemons

libvirtd or the modular virtqemud, virtnetworkd, virtsecretd…, on AF_UNIX sockets, running in the background and taking guests back after a restart.

QEMU with WHPX

<domain type='whpx'>: start, stop, suspend, resume, screenshots, QMP, NIC hotplug, a memory balloon that gives memory back.

virsh console

The guest's serial port on a UNIX socket, typed into from the Windows console, with libvirt's single-session rule and --force.

Virtual networks

NAT and isolated networks without any driver: DHCP, DHCPv6, DNS, IPv6, net-update, leases, guests talking to each other and to the host.

QoS and statistics

domiftune limits, floors and network bandwidth, applied by the network's switch; domifstat counters.

Upgrade in place

Install over running daemons, networks and guests; edited configuration files are kept.

Quick start

Windows 10 1803 or later, x64, with MSYS2 (UCRT64) and QEMU for Windows built with the patch in windows/qemu.

  1. Build and install from an MSYS2 UCRT64 shell: 
    git clone --recurse-submodules https://github.com/EGKrb/libvirt-windows
cd libvirt-windows
windows/build.sh deps
windows/build.sh
  2. Put install\bin, C:\msys64\ucrt64\bin and QEMU on PATH, then start the daemons: 
    install\sbin\virtnetworkd.exe --daemon
install\sbin\virtqemud.exe --daemon
  3. Define a guest of type whpx and start it, as with libvirt anywhere: 
    virsh -c qemu:///system define guest.xml
virsh -c qemu:///system start guest

The README has a complete guest definition, how to stop a daemon and where the files are.
